Before changing boundaries, schemas, or flows

For changes to product boundaries, admission or authority rules, schemas, data flows, or shared contracts, read docs/architecture/current-state.md, target-state.md, and component-map.md, and update affected Mermaid nodes and the map in the same change (AGENTS.md:3). Mark proposed and implemented behavior separately, with code or design sources, verification, Linear work, and ADR links. Keep private source material out of diagrams.

Set up and check

The Quick start syncs the locked environment with uv sync --extra dev --locked, activates .venv, and runs make check (README.md:33). Also run node scripts/check-architecture.mjs to check diagram IDs and local links, as AGENTS.md and the README both ask. When the virtual environment is not activated, use the explicit .venv/bin path to pkmcanon (README.md:42).

Ingest and validate

The Quick start commands are ingest-roam, validate, audit-fidelity, and ingest-markdown (README.md:36). They are Typer commands registered on one app in src/pkmcanon/cli.py:46; for example ingest-roam writes and validates an authoritative package, and validate checks schemas, references, inventory, hashes, and fidelity. For a private source, pass the reviewer identity with --principal instead of relying on the default local-operator (README.md:44).

Review before anything becomes active

The reviewable flow (README.md:49) proposes methodology rules or domain claims, renders a review page, records an approval or rejection with review, and only then publishes. Publication reads the append-only review ledger and selects approved proposals only (README.md:74). The review HTML contains source excerpts, so keep the output private. Do not hand-edit the ledger, and do not treat an unreviewed proposal as active.

Docs, Notion, and sibling repos

Repo docs are authoritative; important changes are mirrored to Canonworks Notion with the source branch, revision, and content digest (AGENTS.md:3). The detailed workflow lives in the sibling canon-flow repo, and the cross-product flows are described in canon-flow/docs/orientation/system-flows.html.
